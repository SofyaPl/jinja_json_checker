# jinja_json_checker

Проверка синтаксиса **JSON** и **шаблонов Jinja2, которые собирают JSON**
(`{"name": {{ user.name | tojson }}}`). Ищет и типичные «невидимые» ошибки: умные кавычки
`“ ” ‘ ’` вместо обычных, неразрывные пробелы, пробелы нулевой ширины.

- Работает **с выделенным текстом**: выделили код в редакторе на веб-странице → нажали значок
  расширения или сочетание клавиш.
- Результат показывается **в окне поверх страницы**: список проблем и ваш код с подсвеченными
  местами. Окно можно двигать и менять его размер.
- **Ничего не исправляет само** и не меняет страницу: показывает, что и где заменить,
  исправляете вы.
- Работает **полностью офлайн**: текст никуда не отправляется, интернет не нужен.

Основной способ — расширение для браузеров на Chromium. Дополнительно есть служба macOS
и командная строка (нужен Python 3.9+, который уже есть на macOS; сторонние библиотеки не нужны).

## Что и в каком порядке проверяется

Проверка идёт по уровням. Пока не исправлены ошибки верхнего уровня, проверить следующий
невозможно, поэтому **после исправления могут найтись новые ошибки** — проверяйте снова,
пока не останется ни одной.

1. **Символы** — умные кавычки, неразрывные и невидимые пробелы. Находятся все сразу.
2. **Теги шаблона** — незакрытые `{{ }}` и `{% %}`, `}` вместо `}}`, непарные скобки внутри
   тега, незакрытые `{% if %}` / `{% for %}`, лишние `{% endif %}`, опечатки в тегах.
   Если здесь есть ошибка, JSON не проверяется: без исправных тегов нельзя понять, где в тексте
   JSON. Окно проверки сообщает об этом красной плашкой.
3. **JSON** — пропущенные и лишние запятые, незакрытые скобки, одинарные кавычки, `True`
   вместо `true`, комментарии. Проверка останавливается **на первой ошибке**: после неё
   программа не может надёжно понять, что имелось в виду, и следующие сообщения были бы
   ложными. Об остановке тоже сообщает красная плашка.
   Предупреждения (не ошибки): повторяющиеся ключи в объекте и повторы `"key"` / `"name"` /
   `"id"` в списке объектов.

## Установка и обновление

Первая установка, в Терминале:

```sh
git clone https://github.com/SofyaPl/jinja_json_checker.git ~/jinja_json_checker
```

Обновление (скачивает последнюю версию и заменяет ею файлы в папке; свои правки в этой папке
не храните — они будут стёрты):

```sh
cd ~/jinja_json_checker && git fetch && git reset --hard origin/main
```

Какая версия сейчас стоит (последнее изменение и дата):

```sh
cd ~/jinja_json_checker
git log -1 --format='%h %ad %s' --date=short
```

После обновления перезагрузите расширение: `chrome://extensions` → на карточке
«JSON / Jinja checker» круглая стрелка **Reload**.

## Расширение для браузера

### Установка

1. Откройте в браузере адрес `chrome://extensions`.
2. Включите **Developer mode** (справа вверху).
3. Нажмите **Load unpacked** и выберите папку `jinja_json_checker/extension` в домашней папке.
   Не удаляйте и не перемещайте её после установки.
4. Чтобы значок был всегда виден: значок-пазл справа от адресной строки → булавка рядом
   с «JSON / Jinja checker».
5. Сочетание клавиш по умолчанию — **Control+Shift+Y**. Проверить или сменить его:
   `chrome://extensions/shortcuts` → «JSON / Jinja checker».

### Как пользоваться

Выделите код в редакторе (⌘A) и нажмите значок расширения или сочетание клавиш. Откроется окно
проверки: сводка, список проблем и код с подсвеченными местами. Щелчок по проблеме прокручивает
код к нужной строке. Для умных кавычек и невидимых символов показано, на что заменить.

Окно открывается у левого края. Его можно перетащить за заголовок, изменить размер за правый
нижний угол, а кнопкой ⇆ прижать к другому краю экрана. Положение и размер запоминаются.
Закрыть — **Esc** или ×.

Расширение запускается только по нажатию значка или сочетания клавиш и получает доступ лишь
к текущей вкладке и только в этот момент.

### Как расширение получает текст

Редакторы кода на веб-страницах рисуют текст сами и не отдают выделение напрямую. Расширение
вызывает копирование и забирает текст из него, поэтому после проверки в буфере обмена может
оказаться выделенный код — окно предупреждает об этом. Если текст получить не удалось, окно
скажет об этом и предложит вставить текст вручную.

### Если что-то не работает

На карточке расширения в `chrome://extensions` появится кнопка **Errors**: вверху будет текст
ошибки. Значок расширения в этом случае показывает «!», а при наведении — тот же текст.

## Служба macOS (необязательно)

Для обычных полей ввода и программ, где выделение доступно системе: выделили текст →
правая кнопка → **Services** → «Проверить синтаксис». В редакторах кода на веб-страницах
обычно не работает — там используйте расширение.

1. **Automator** → **New Document** → **Quick Action**.
2. **Workflow receives current**: **text** in **any application**.
3. Перетащите действие **Run Shell Script**. **Shell**: `/bin/zsh`, **Pass input**: **to stdin**.
4. Скрипт:

   ```sh
   cd "$HOME/jinja_json_checker" && /usr/bin/python3 -m jinja_json_checker service-check
   ```

5. ⌘S, имя «Проверить синтаксис».

Горячая клавиша: **System Settings** → **Keyboard** → **Keyboard Shortcuts** → **Services** →
**Text** → «Проверить синтаксис».

Если ошибок нет, появится уведомление; если есть — откроется отчёт в браузере. Отчёт сохраняется
во временную папку пользователя и перезаписывается при каждой проверке.

## Командная строка

```sh
cd ~/jinja_json_checker
python3 -m jinja_json_checker check file.json           # отчёт в терминале
python3 -m jinja_json_checker check file.json --html r.html
pbpaste | python3 -m jinja_json_checker check           # проверить текст из буфера обмена
```

`--mode`: `auto` (по умолчанию), `json`, `template`.

## Ограничения

- Внутри `{% if %}…{% elif %}…{% else %}` для JSON проверяется только первая ветка.
  Запятые на границах блоков `{% if %}` и `{% for %}` не проверяются: они зависят от данных.
- Если редактор находится во фрейме с другого адреса, расширение может не получить к нему
  доступ. Тогда используйте ручную вставку в окне проверки.

## Разработка

```sh
python3 -m unittest
```

Проверка написана дважды: на Python (`jinja_json_checker/`, для службы и командной строки)
и на JavaScript (`extension/checker.js`, для расширения). Тест `tests/test_parity.py` сравнивает
обе версии на тысячах вариантов; для него нужен Node.js.
